## Weaknesses

-   **Thread-based job execution**: Jobs run in daemon threads within the Flask process (`jobs_worker.py:132`). This means jobs are lost on process restart, can't scale across workers, and there's no job persistence/retry after crash.
-   **Duplicate `Flask-Limiter` in requirements.txt** (listed twice at lines 8 and 11)
-   **Model `__init__` boilerplate**: Every model repeats the same `__init__` pattern (`for key, value in kwargs.items(): if hasattr(self, key): setattr(self, key, value)`). This is copy-pasted across 10+ models instead of being inherited from `BaseModel`.
-   **Inconsistent `to_json()` implementations**: Some models use manual key lists, others use `__table__.columns`. `BaseModel.to_json()` exists but is overridden everywhere.
-   **`Config` class has class-level AND instance-level initialization**: `app_settings = get_settings()` at class level (line 22 of `flask_config.py`) AND `app_settings = get_settings()` in `__init__` — confusing dual initialization.
-   **Service instantiation in route `__init__`**: Each MethodView creates service instances in `__init__` (e.g., `self.service = AdminService()`), meaning a new service is created per-request. These could be class-level or use dependency injection.
-   **`UsersRoutes` has dead backward-compatibility code**: Lines 117-130 contain TODO-marked wrapper methods that duplicate MethodView functionality.
-   **`templates.py` has a dead method**: `TemplatesRoutesFuncs.download_templates_json()` calls `create_json_file()` (module-level function) but also defines `self.create_json_file()` — the instance method shadows but is never called by `download_templates_json`.
-   **Large route files**: `owid_charts.py` (280+ lines) and `templates.py` (270+ lines) combine business logic with HTTP handling.
-   **`lru_cache` on `get_settings()` with no invalidation**: Settings are cached forever — runtime changes to environment variables are silently ignored.

## Critical Issues

> ⚠️ Issues that can cause failures, data loss, or security incidents.

1. **Daemon threads lose jobs on restart** (`jobs_worker.py:132`): `threading.Thread(daemon=True)` means all running jobs are killed when the process exits. No graceful shutdown or job recovery mechanism exists.
2. **Race condition in `upsert_by`** (`crud_service.py:197-237`): The comment acknowledges the TOCTOU race between `get_by()` and `create()`. While `IntegrityError` retry is implemented, the rollback may not fully clean up the session state in all SQLAlchemy configurations.
3. **`SECRET_KEY_FALLBACKS` parsed from comma-separated env var** (`flask_config.py:38`): If any fallback key contains a comma, it will be silently split. No escaping mechanism exists.
4. **No input sanitization on log file viewer** (`errors_route.py`): While `re.escape()` is used for search, the `file_name` parameter is only checked against a list of existing files — path traversal is prevented, but the log viewer streams raw log content that could contain XSS payloads if rendered unsafely in templates.
5. **`WikiSiteClient._get_user_site` silently swallows all exceptions** (`wikisite_client.py:45-52`): A broad `except Exception` catches crypto errors, configuration errors, and programming bugs, returning `None` instead of surfacing the root cause.
