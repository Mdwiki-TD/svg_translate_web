## Architecture & Code Quality Review

-   **Code organization**: Mirrors the source tree structure (`tests/unit/admin/routes/` ↔ `src/main_app/admin/routes/`). Clear separation: unit / integration / network.
-   **Design patterns**:
    -   Fixture-based test setup with `conftest.py` providing app, client, DB, and mock objects
    -   `pytest_socket` for network isolation — prevents accidental HTTP calls in unit tests
    -   Session-scoped app fixture for performance (one Flask app for all tests)
    -   Function-scoped DB fixture for test isolation (fresh tables per test)
    -   SQLite view function registration to emulate MySQL-specific functions (`now()`, `YEAR()`)
-   **Maintainability**: Test file naming convention (`test_<module>.py`) makes it easy to find corresponding tests. Fixture reuse via `conftest.py` hierarchy.
-   **Readability**: Test functions follow `test_<behavior>` naming. Assertions are clear.
-   **Scalability**: pytest-xdist support for parallel test execution. Network tests isolated via markers.

## Strengths

-   **Excellent network isolation**: `pytest_socket` with `disable_socket(allow_unix_socket=True)` prevents any accidental network calls. Only tests marked with `@pytest.mark.network` can access the network.
-   **SQLite compatibility layer**: Custom `sqlite_view_functions()` registers MySQL-compatible functions (`now()`, `YEAR()`) so the same ORM code runs against both MySQL (production) and SQLite (tests).
-   **Comprehensive coverage**: ~200+ test files covering models, services, routes, workers, utilities, decorators, and configuration.
-   **Well-structured conftest hierarchy**: Root `conftest.py` + `unit/conftest.py` + `integration/conftest.py` provide appropriate fixtures at each level.
-   **Environment setup before imports**: `conftest.py` correctly sets ALL environment variables before any application import, preventing `RuntimeError` from missing config.
-   **Mock MediaWiki fixtures**: `mock_site`, `mock_page`, `mock_site_pages` fixtures provide reusable test doubles for wiki API testing.
-   **pytest markers**: Clean separation via `@pytest.mark.unit`, `@pytest.mark.network`, `@pytest.mark.enable_socket`.

## Weaknesses

-   **No coverage threshold enforcement**: `pytest-cov` is enabled but no minimum coverage percentage is enforced in CI.
-   **Integration tests may be slow**: Session-scoped app with function-scoped DB means tables are created/dropped per test function — this can be slow for large test suites.
-   **No property-based testing**: No use of `hypothesis` or similar for fuzz testing.
-   **No test for deployment scripts**: Shell scripts in `toolforge/` have zero test coverage.
-   **JavaScript tests are minimal**: Only one JS test file (`macros.test.mjs`) for DataTables.
-   **No performance/benchmark tests**: No tests for response time, query performance, or job throughput.
-   **`conftest.py` uses `sys.path` manipulation**: Lines 29-37 manually insert paths into `sys.path` instead of using proper package installation (`pip install -e .`).
